# プロジェクト初期化（CLAUDE.md / docs/plan.md の作成）

デスクトップ版 Claude のチャットから呼び出す前提のスキル。ローカルの `~/.claude/CLAUDE.md` は読めないため、同じ内容を GitHub の公開リポジトリから取得して使う。生成したファイルはダウンロードしてもらい、ユーザーがプロジェクトに配置する。

## 手順

### 1. グローバル CLAUDE.md を取得する

次の URL から取得する。

```
https://raw.githubusercontent.com/shinshu68/dotfiles/refs/heads/master/claude/CLAUDE.md
```

- bash の `curl -sS -w "%{http_code}"` で取得し、HTTP 200 であることを確認する
- 失敗した場合は web_fetch で同じ URL を試す
- それでも取得できなければ、取得できなかった旨を伝え、内容を貼り付けてもらうよう依頼して止まる。推測で中身を補わない

取得した内容は「プロジェクトでも常に読み込まれる前提のルール」として扱う。

### 2. プロジェクトの情報を集める

会話・添付ファイル（README、既存コード、要件メモなど）からわかることを先に整理し、足りないものだけを質問する。一度に聞きすぎず、重要なものから聞く。

集めたい情報：

- プロジェクトの目的・背景（何を解決するか、誰が使うか）
- スコープ（やること／やらないこと、最初のゴール）
- 技術スタック（言語、フレームワーク、主要ライブラリ、実行環境）
- ディレクトリ構成の想定
- ビルド・テスト・実行・lint のコマンド（決まっていれば）
- プロジェクト固有のルールや制約（命名規則、外部 API、データの扱いなど）
- 進め方（マイルストーン、優先順位）

決まっていない項目は無理に埋めず、plan.md の「未決事項」に回す。

### 3. CLAUDE.md を作成する

方針：**グローバル CLAUDE.md との差分だけを書く**。グローバルはプロジェクトでも常に読み込まれるため、言語設定・Git 運用・秘匿情報の扱いなど、グローバルにある内容を書き写さない。

構成の目安：

```markdown
# <プロジェクト名>

<1〜2行の概要>

開発方針・スコープ・設計の詳細は docs/plan.md を参照する。

## 技術スタック
## ディレクトリ構成
## コマンド
（ビルド・テスト・実行・lint。1コマンドずつコードブロックで）
## プロジェクト固有のルール
```

- グローバルと異なる運用をするとき（例：このプロジェクトは develop を使わない）だけ、「グローバルの〇〇より優先する」と明記して書く
- 決まっていないセクションは見出しごと省くか、「未定（docs/plan.md の未決事項を参照）」とする
- 簡潔に保つ。CLAUDE.md は毎回読み込まれるため、説明的な文章や背景は plan.md に寄せる

### 4. docs/plan.md を作成する

開発方針をまとめる、人が読むためのドキュメント。

構成の目安：

```markdown
# <プロジェクト名> 開発方針

## 目的・背景
## スコープ
### やること
### やらないこと
## 技術選定
（選んだ技術と、選んだ理由）
## 設計方針
（アーキテクチャ、データの流れ、主要なモジュールの役割など）
## 進め方
（マイルストーン、最初に作るもの）
## 未決事項
```

- 技術選定には理由を添える（後から見直すときの判断材料になるため）
- ユーザーが言っていないことを決定事項として書かない。提案する場合は「案」と明記するか、未決事項に入れる

### 5. ファイルを渡す

- `/mnt/user-data/outputs/CLAUDE.md` と `/mnt/user-data/outputs/docs/plan.md` に Markdown ファイルとして書き出し、present_files で渡す
- Claude Docs や公開ページ（Artifact）にはしない。ローカルのリポジトリに置くファイルなので、素の Markdown ファイルで渡す
- 渡した後は、内容の要点を2〜3行で伝えるにとどめ、配置場所（プロジェクトのルートに CLAUDE.md、docs/ に plan.md）を一言添える

## 修正を頼まれたとき

同じ会話の中で修正を頼まれたら、該当箇所だけを直して同じパスに書き出し直し、再度 present_files で渡す。グローバル CLAUDE.md は会話の中で取得済みならそれを使い、再取得しない。

# desktop-prefs

グローバルの CLAUDE.md と、Claude Code で使っている出力スタイルを、デスクトップ版 Claude の個人設定 (設定画面の「Claude に考慮してほしい個人設定」の欄) に貼り付ける用のテキストに変換して出力する。出力スタイルを含めるのは、Claude Code とデスクトップ版で同じ口調 (キャラクター) で話してもらうため。

ユーザーの操作は「スキルを呼ぶ → 出力をコピーする → 設定欄に貼り付ける」だけにしたい。そのため、出力はコピーボタン1回で全文を取れる1つのコードブロックにまとめ、前置きや確認の質問は挟まない。

## なぜ変換が必要か

CLAUDE.md と出力スタイルは Claude Code 向けに書かれていて、デスクトップ版では意味をなさない、または誤解を招く記述が含まれる。

- デスクトップ版にはない仕組み (`/commit-suggest` などのスキル名、AskUserQuestion などのツール名、自動メモリ、環境情報の Platform 欄、サブエージェント、ツール呼び出し) を前提にした記述
- リポジトリを直接操作する Claude Code の作業手順 (ブランチ運用、コミットの手順、スクリプトの実行方法、コードレビューなど)
- 再発防止のために付けた日付タグや、経緯の説明
- 出力スタイルの frontmatter (`name`・`description`・`keep-coding-instructions`) のような、Claude Code の設定のための項目

個人設定はすべての会話で毎回読み込まれるので、関係のない記述は短く削るほど、残したルールが効きやすくなる。

## 手順

### 1. CLAUDE.md と出力スタイルを取得する

dotfiles リポジトリの中で実行されたときは、ローカルのファイルを読む。それ以外は GitHub から取得する。dotfiles にはまだ push していない変更があることが多く、GitHub から取ると直したばかりの内容が反映されないため。

読むファイルは次の3つ。CLAUDE.md・settings.json・出力スタイルは同じ読み込み元 (ローカルか GitHub のどちらか) からそろえて読み、混ぜない。

- `claude/CLAUDE.md`: グローバルの CLAUDE.md
- `claude/settings.json`: 使っている出力スタイルの名前 (`outputStyle`) を調べるため
- `claude/output-styles/` の中の出力スタイル: 1-4 で決める

#### 1-1. dotfiles の中かどうかを判定する

origin の URL で判定する。ディレクトリ名ではなく origin を見るのは、別の場所や別の名前でクローンしても正しく判定できるようにするため。

```bash
git rev-parse --show-toplevel
```

```bash
git remote get-url origin
```

- origin が次のどちらかなら dotfiles の中とみなす。末尾の `.git` はあってもなくてもよい
  - SSH 形式: `git@github.com:shinshu68/dotfiles.git`
  - HTTPS 形式: `https://github.com/shinshu68/dotfiles.git`
- 次の場合はどれも dotfiles の外として扱い、1-3 に進む
  - git リポジトリの外で実行された (`git rev-parse` が失敗する)
  - git が使えない環境で実行された (デスクトップ版など)
  - origin が設定されていない、または別のリポジトリを指している

#### 1-2. dotfiles の中なら、ローカルのファイルを読む

`git rev-parse --show-toplevel` の結果をリポジトリのルートとし、そこを起点に各ファイルを読む。ルートを起点にするのは、dotfiles のサブディレクトリから実行しても同じファイルを読めるようにするため。

- 作業ツリーのファイルをそのまま読む。未コミットの編集も含めてよい (直してすぐ確かめられるようにするため)
- CLAUDE.md の読み取りに失敗したら、3つとも 1-3 で取得し直す
- settings.json や出力スタイルだけ読めなかった場合は、出力スタイルなしで進める (1-4)

#### 1-3. それ以外は、URL から取得する

次の URL を起点に、各ファイルのパスを付けて取得する (dotfiles リポジトリの main ブランチ。push 済みの内容が対象になる)。

```
https://raw.githubusercontent.com/shinshu68/dotfiles/refs/heads/main/
```

例: `https://raw.githubusercontent.com/shinshu68/dotfiles/refs/heads/main/claude/CLAUDE.md`

- bash で `curl -sS -w "%{http_code}"` を使って取得し、HTTP 200 であることを確認する
- 失敗したら WebFetch (web_fetch) で同じ URL を試す。要約ではなく全文を得る必要があるので、要約しか返らない場合は失敗とみなす
- CLAUDE.md が取れなければ、取得できなかった旨を伝え、CLAUDE.md の内容を貼り付けてもらうよう頼んで止まる。推測で中身を補わない
  - 貼り付けてもらった場合は、出力スタイルは含めない。ユーザーが出力スタイルの内容も一緒に貼り付けたときだけ含める
- settings.json や出力スタイルだけ取れなかった場合は、止まらずに出力スタイルなしで進める (1-4)

#### 1-4. 含める出力スタイルを決める

settings.json の `outputStyle` の値から、Claude Code と同じ決め方で出力スタイルのファイルを特定する。

- `outputStyle` がない・空・`default` のときは、出力スタイルを含めない
- ローカルのときは、`claude/output-styles/` の中の `.md` ファイルのうち、frontmatter の `name` が `outputStyle` の値と完全に一致する (大文字・小文字も区別する) ものを使う。`name` がないファイルは、拡張子を除いたファイル名で比べる
- URL のときはディレクトリの一覧を取れないので、`claude/output-styles/<outputStyle の値>.md` を取得し、上と同じ方法で名前が一致するか確かめる
- 一致するファイルが見つからなければ、出力スタイルを含めずに進む。そのことは手順5の一言で知らせる

### 2. CLAUDE.md の各ルールを「残す・書き換える・取り除く」に振り分ける

見出し単位ではなく、ルール1行ずつ判断する。判断の軸は「デスクトップ版の Claude がこのルールを読んで、行動を変えられるか」。

**残す** (そのまま、または表現を整えて残す)
- 言語設定、応答スタイル (称賛の前置きをしない、誤字の扱い、括弧の書き方、用語の扱いなど)
- 事前に確認する操作、秘匿情報の扱い
- どの環境でも通じる注意点 (止められた指示は再開しない、テストデータに実在の固有名詞を使わない、確認事項が一部しか答えられていなければ聞き直す、など)

**書き換える** (意図は残し、デスクトップ版で通じる表現にする)
- ツール名 → 一般的な言い方にする。例: 「AskUserQuestion の選択肢 UI」→「選択肢の UI」、「ツール呼び出しの拒否」→「操作の拒否」
- 環境の記述 → Platform 欄での判定や Claude Code が使うシェルの話は除き、ユーザーの環境と、ユーザーに示すコマンドの書き方だけにする。例: 「PC は Windows で、開発は WSL2 (Ubuntu) でも行う」「WSL2 向けのコマンドは fish で、Windows 向けのコマンドは PowerShell で動く書き方にする」
- 事前確認の対象 → デスクトップ版でありうる外部への操作 (メールやメッセージの送信、投稿、公開・共有など) も含む形に一般化する。`npm -g`・`apt`・`sudo` のような具体例は「ソフトウェアやパッケージのインストール、管理者権限が必要な操作」のようにまとめる
- 秘匿情報 → `.env` / `.env.example` の運用のような Git 前提の手順は除き、「コードや設定ファイルに直書きしない」「生成物やログに含めない」という原則を残す
- 対象範囲の記述 → 「CLAUDE.md・スキル・コミットメッセージにも適用」のような Claude Code の作業物の列挙は、「応答と、作成するファイル (ドキュメント、コードなど) の全てに適用」のように言い換える
- 注意点の中に Claude Code の手順が混ざっているもの → その部分だけ除く。例: 「確認事項が残っているときに、同じ返答でコミットメッセージの候補を出さない」→ 「作業の終わりに確認事項が残っている場合は、それを出力して止まる」

**取り除く**
- Git 運用 (ブランチ、コミットの手順やメッセージ形式) とコードレビューの節
- スキル・スクリプト・自動メモリ・PR の書き方など、Claude Code やリポジトリでの作業にしか関係しないルール
- 日付タグ (`[2026-09-05]` など)、ルールができた経緯の説明

判断に迷うルールは、意図がデスクトップ版の会話でも活きるなら書き換えて残し、Claude Code の操作手順そのものなら取り除く。CLAUDE.md に今後新しい節やルールが増えても、この軸で同じように判断する。

### 3. 出力スタイルを変換する

手順1-4で出力スタイルを特定できたときだけ行う。frontmatter は除き、本文を手順2と同じ軸で振り分ける。

**残す**
- キャラクターの設定 (名前・一人称・ユーザーの呼び方・口調・文末や絵文字の扱い)。口調の例文や言い回しは変えずにそのまま写す。言い換えるとキャラクターがずれるため
- キャラクターより個人設定のルールを優先させる指示と、口調のためにしてはいけないことの一覧
- Claude アプリ (デスクトップ版・モバイル版) での扱いを決めた記述。中に挙げた項目 (ツール呼び出しの合間の文章など) と理由の一文も含めて、省かずに写す。アプリでの口調の出し方を決めるために書いたもので、デスクトップ版でこそ必要なため

**書き換える**
- 「CLAUDE.md の指示に従う」のような参照 → 「この個人設定のほかの指示に従う」のように、個人設定の中で通じる言い方にする
- 口調を使わない対象の一覧 → デスクトップ版でも作るもの (コード・ドキュメント・CLAUDE.md・スキルなどファイルに書く内容、コミットメッセージや PR の本文など外部に出る文章、他の人に向けて作る資料) は残す。そのうえで、デスクトップ版でありうるもの (メールやメッセージ、投稿など、他の人に送る文章) を加えて一般化する
- 言語の指示 → 個人設定の言語設定と重なる内容は、言語設定の節にまとめて重複させない。「ツールの出力が英語ばかりのときも」のような Claude Code 前提の場面は、「読んだ資料や検索結果が英語ばかりのときも」のようにデスクトップ版で起こる場面に言い換える

**取り除く**
- 「Claude Code では、ツール呼び出しの合間の一言を含む」「サブエージェントに渡すプロンプト」のような、Claude Code に限った場面や仕組みについての記述

### 4. 整形する

- 先頭の `# 個人設定` のような文書タイトルは付けない。`## 言語設定` のような節見出しから始める
- 節の順序は CLAUDE.md に合わせる。中身が空になった節は見出しごと消す。「全プロジェクト共通の注意点」は「注意点」とする
- 出力スタイルの節は、言語設定の節の直後に置く。どの応答にも関わる指示なので、前の方に置いて効きやすくするため。出力スタイルの `#` の見出しは `##` に下げ、節の順序は出力スタイルに合わせる
- 1ルール1行の箇条書きにして、各行は短く言い切る。理由の説明は、ないと誤解されるものだけ残す
- 括弧は半角の () を使う (CLAUDE.md のルールに従う)
- 事実を足さない。CLAUDE.md や出力スタイルにないルールを補ったり、意味を強めたり弱めたりしない

### 5. 出力する

返答は次の形にする。

1. 読み込み元を添えた一言。手順1でどこから読んだか、どの出力スタイルを含めたかを、コードブロックの前のこの一言で知らせる (ローカルのつもりが GitHub の内容だった、含めたつもりのスタイルが入っていなかった、という取り違えに気づけるようにするため)。口調は会話で使っている口調に合わせる
   - 伝えること: デスクトップ版の個人設定に貼り付ける内容であることと、何から作ったか
   - 何から作ったかは、ローカルなら「ローカルの CLAUDE.md と出力スタイル <name> (dotfiles)」、URL なら「GitHub の CLAUDE.md と出力スタイル <name> (main ブランチ)」、貼り付けてもらった場合は「貼り付けてもらった CLAUDE.md」
   - 出力スタイルを含めなかった場合は出力スタイルに触れない。`outputStyle` が設定されているのにファイルが見つからなかった、または取得できなかったときは、出力スタイル <name> が見つからず含めていないことも伝える
2. 変換後の全文を入れた **コードブロック1つ**。言語指定は `text` にする (Markdown として描画されず、見出しの `##` などもそのままコピーできるようにするため)。中身にバッククォート3つが含まれる場合は、フェンスを4つ以上のバッククォートにして崩れないようにする

コードブロックの後には何も書かない。削除・書き換えた項目の一覧や補足も付けない (ユーザーはコピーするだけで、出力を短く保ちたいため)。ユーザーに聞かれたときだけ説明する。

ファイルの作成や Artifact・ドキュメントへの書き出しはしない。コピーして貼るだけの使い捨ての出力なので、会話の中で完結させる。

## 修正を頼まれたとき

同じ会話で「この行は残して」「ここはもっと短く」などと言われたら、取得済みの CLAUDE.md と出力スタイルを使って (再取得しない) 該当箇所を直し、全文を同じ形のコードブロックで出し直す。貼り付け直す手間を減らすため、差分ではなく全文を出す。

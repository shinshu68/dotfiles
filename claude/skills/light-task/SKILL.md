# light-task

制限の残りが少なくても、軽い作業なら終えられることが多いです。このスキルは、ユーザーが `/light-task` を付けて頼んだ作業1件に限って、CLAUDE.md の「使用量制限」の決まり (通知を受けたらキリのいいところで止まる) を適用せずに最後まで進めるためのものです。

例外を付けるかどうかはユーザーが決めます。Claude が自分の判断でこのスキルを使ったり、対象をほかの作業に広げたりしないでください。止まるべき場面で止まらないと、上限に達した時点で作業が中途半端なまま残ってしまいます。

## 対象の作業

- `/light-task` の引数に書かれた作業1件だけが対象です。
- 完了報告をした時点でスキルの作業は終わります。同じセッションの次の指示には、例外を広げません。次の指示の途中で通知が来たら、CLAUDE.md の決まりどおり止まります。改めて `/light-task` を付けて頼まれたら、その作業がまた対象になります。
- 引数がないときは、直前の会話から推測しません。何をするか聞き返して止まります。推測すると、例外が付く範囲が曖昧になるためです。

## 進め方

### 1. 着手前に見積もる

作業が「軽い作業」に収まるかを見積もります。

- 軽い作業の例: 数ファイルの編集、短い調査、コミットメッセージの候補出し
- 重い作業の例: 高い effort のコードレビュー、多数のファイルの調査、サブエージェントの起動、長いテストの実行

収まらないと判断したら、着手せずに理由 (どの部分が重いか) を添えて、続けるかどうかを確認します。重い作業は途中で上限に達しやすく、達すると結果が何も残らないことがあるためです。

### 2. 作業を進める

usage-guard の通知 (「課金プランの使用量制限の5時間枠が上限の N% に達しています (リセット: ...)」のような文) がツールの結果に付いても、止まらずに続けます。

通知を受けたら、その内容 (枠の種類・使用率・リセット時刻) を完了報告まで覚えておきます。枠ごとにしきい値が違うので、5時間枠の通知のあとに7日枠の通知が別に来ることもあります。来たものはすべて覚えておきます。

通知を受けたあとは、上限 (100%) に達すると Claude Code 側で応答が止まります。これはこのスキルでは避けられません。いつ止まっても被害が小さくなるように進めます。

- 1ファイルずつ書き終えてから次へ進み、編集中のファイルを壊れた状態で長く残さない
- 必要のない調査やツール呼び出しを足さない

### 3. 途中で重くなったら止まる

進めるうちに見積もりより重くなったと気づいたら (調べる範囲が広がった、直すファイルが増えた、など)、キリのいいところで止まります。キリのいいところとは、編集中のファイルを壊れた状態で残さず、1つの手順を終えたところです。止まったら、次の3つを伝えて、続けるかどうかを確認します。

- どこまで進んだか
- 残りの作業
- 重くなった理由

### 4. 完了報告をする

作業の結果を報告します。作業中に通知を受けていたら、報告の最後に次の形で添えます。

```
使用量の通知 (この作業中に受信):
- 5時間枠: 92% (リセット: 2026-10-25 18:00)
```

これを省かないでください。usage-guard は同じ枠について1セッションで1回しか知らせません。ここで伝えないと、ユーザーは制限が近いことを知らないまま次の作業を頼むことになり、Claude もその作業で通知を受けずに上限まで進んでしまいます。

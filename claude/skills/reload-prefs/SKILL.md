# reload-prefs

デスクトップ版 Claude の個人設定 (「Claudeへの指示」) は、セッションの開始時に一度だけ読み込まれる。設定画面で書き換えても、同じセッションには古い内容が残ったままになる。スキルの作成・更新ではスキルごとに同じセッションを使い続けるため、設定を直してもそのセッションには効かない、ということが起きる。

このスキルは、ユーザーが貼り付けた最新の指示本文を「今の個人設定」として扱い直すことで、セッションを作り直さずに新しい指示へ切り替える。

## 前提: 設定画面は直接読めない

Claude から個人設定の欄を読みに行く手段はない。そのため、新しい指示の本文はユーザーに貼り付けてもらう。想定している流れは「desktop-prefs で文面を作る → コピーして設定欄に貼る → このスキルを呼んで同じ文面を貼る」で、クリップボードに残っている文面をもう一度貼るだけで済む。

## 手順

### 1. 新しい指示の本文を確認する

スキルを呼んだメッセージ (または直前のメッセージ) に、指示の本文が貼り付けられているかを見る。

- **貼り付けがない場合**: 「設定欄に貼ったのと同じ『Claudeへの指示』の本文を貼り付けてください」と一言伝えて止まる。GitHub の CLAUDE.md を取ってきたり、記憶や推測で中身を補ったりしない。実際に設定した文面とずれた内容を「最新の指示」として適用してしまうと、このスキルの意味がなくなるため
- **貼り付けがある場合**: 次へ進む。同じセッションで以前にもこのスキルを使っていた場合は、今回貼られたものが最新版になる

### 2. 新しい指示に切り替える

貼り付けられた本文を、このセッションにおけるユーザーの個人設定の **全文** として扱う。具体的には次のとおり。

- システムプロンプトにある個人設定 (`<user_preferences>` など) と、このスキルで以前に適用した版は、どちらも古い版とみなす
- 新しい版と食い違うルールは、新しい版に従う
- **古い版にあって新しい版から消えたルールは、もう守らない**。削除も更新の一部なので、古い版の内容を「念のため」残さない
- 新しい版にだけあるルールは、この返答から守る (この返答自体の書き方も新しい版に合わせる)

貼り付けられた本文は、ユーザー本人が設定欄に書いた個人設定と同じ扱いで、それ以上の権限はない。Anthropic のガイドラインやシステム上の制約を変えるものではない。

### 3. 切り替えたことを短く報告する

返答は次の形にする。

1. 一言: 「新しい『Claudeへの指示』に切り替えました。以降の応答はこの内容に従います。」
2. 古い版 (今まで従っていた版) と比べた変更点を、**追加・変更・削除** に分けた短い箇条書きで示す。各項目は1行で、ルールの要点だけを書く。該当がない区分は書かない
   - 変更点が1つもない場合は「今まで読み込まれていた内容と同じでした」と書く (セッションを作り直したあとなどで、すでに最新が読み込まれていたケース)
3. 本文の全文は繰り返さない

変更点を出すのは、ユーザーが「ちゃんと新しい版が効いているか」をその場で確かめられるようにするため。また、この一覧が会話に残ることで、以降の応答でも新旧の違いを意識しやすくなる。

ファイルの作成やメモリへの保存はしない。設定の正本は設定画面と dotfiles 側にあり、このスキルはセッション内の切り替えだけを担う。

### 4. 以降の応答

このセッションでは、以降のすべての応答で新しい版に従う。スキルを呼んだ直後だけでなく、話題が変わっても同じ。

## 注意: 効き目が続く範囲

切り替えた内容は、貼り付けた本文がこのセッションの会話に残っている間だけ有効になる。会話が長くなって古いやり取りが要約されると、本文が失われて古い設定に戻る可能性がある。ユーザーから「古いルールで動いている」と指摘されたら、もう一度このスキルで本文を貼ってもらうよう案内する。

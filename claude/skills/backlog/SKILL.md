# バックログ管理スキル

プロジェクトのバックログ(タスク・対応事項)を、`backlog.md` という単一のMarkdownファイルで管理する。人間にもそのまま読みやすく、Gitなどでバージョン管理もしやすい形式を保つことが目的。

## なぜこの形式か

バックログは「今何が残っていて、何が進行中で、何が終わったか」を一目で把握できることが最も重要。そのためステータスごとにセクションを分け、各セクション内では優先度順に並べる。IDを振るのは、ユーザーが「#003を完了にして」のように短い参照でタスクを指定できるようにするため。

## ファイルの場所

バックログはプロジェクトのディレクトリには置かず、専用のデータフォルダ `~/.claude/backlog-data/` にプロジェクトごとのファイルとして保存する。これはスキル自体の置き場所(`~/.claude/skills/backlog/`)とは別の場所であることに注意する。スキルが更新・再インストールされてもユーザーのバックログデータが失われないようにするため、そして複数プロジェクトのタスクが混ざらないようにするためである。

1. 現在の作業ディレクトリ名(gitリポジトリならその名前を優先)をプロジェクト名として使う。例えば `/home/user/projects/my-app` で作業していれば `my-app` になる。
2. 対象ファイルは `~/.claude/backlog-data/<プロジェクト名>.md`。
3. フォルダ `~/.claude/backlog-data/` が存在しなければ作成する。ファイルが存在しなければ、下記フォーマットで新規作成してよいかユーザーに一言確認してから作る。
4. プロジェクト名が紛らわしい、または複数の候補がある(ディレクトリ名とgit名が異なる等)場合は、どちらを使うかユーザーに確認する。
5. 「今どのプロジェクトのバックログを見ているか」が曖昧なとき(例えばプロジェクト外の場所から呼ばれたときなど)は、ファイルパスをユーザーに伝えてから操作する。
## ファイルフォーマット

```markdown
# プロジェクトバックログ

## 進行中
- [ ] **#004** `優先度:高` タスクのタイトル
      > 背景や詳細のメモ(任意。不要なら省略してよい)

## 未着手
- [ ] **#002** `優先度:中` 別のタスクのタイトル
- [ ] **#003** `優先度:低` さらに別のタスク
- [ ] **#005** `優先度:未設定` 優先度をまだ決めていないタスク

## 完了
- [x] **#001** `優先度:中` 完了したタスク
```

ルール:
- セクションは常に「進行中」「未着手」「完了」の3つ、この順番で保持する。空のセクションでも見出しは残す。
- 各セクション内は優先度順(高→中→低→未設定)、同じ優先度内はID昇順で並べる。「未設定」は優先度を決めていないという意味なので、常に一番下に置く。
- IDは `#001` のように3桁ゼロ埋めの連番。新規タスクにはファイル内の最大ID+1を割り当てる(採番の欠番は気にしなくてよい)。
- チェックボックスは「完了」セクションのタスクのみ `[x]`、それ以外は `[ ]`。
- 詳細メモは任意。ユーザーが背景・理由・メモなどを添えたときだけ `>` の引用行で1〜数行つける。なければ省略し、タイトル行だけにする。
## 操作

ユーザーの発言から、以下のどの操作かを判断して実行する。複数の操作が一度に依頼されたら、まとめて処理してよい。

### タスクの追加
- タイトルを聞き取る(会話から明らかならユーザーに聞き返さなくてよい)。
- 優先度が明示されていなければ、勝手に推測せず「未設定」として登録する。後から優先度付けの操作でまとめて整理できる。
- ステータスは通常「未着手」。ユーザーが「今すぐ着手する」のように言えば「進行中」に置く。
- 新しいIDを採番し、該当セクションの適切な位置(優先度順)に挿入する。
### ステータス更新
- ユーザーがID(例:「#003」)またはタスク名で指定してきたら、そのタスクを該当セクションから正しい新セクションへ移動する。
- 「完了」に移すときはチェックボックスも `[x]` にする。
- IDだけで曖昧な場合は、タイトルで一致するタスクを探して確認する。複数候補があれば、どれか確認する。
### 優先度付け・並べ替え
- ユーザーが優先度を指定したら該当タグを書き換え、そのセクション内で並べ替える。
- 「並べ替えて」とだけ言われた場合は、ファイル全体を上記ルール(セクション内で優先度順→ID順、未設定は最後)に整える。
- 手動での順番指定(「これを一番上に」等)があれば、それを優先度より優先してその通りに並べる。
- 「優先度が未設定のタスクは?」「優先度をつけていないタスクを教えて」のように聞かれたら、`優先度:未設定` のタスクだけを抜き出して一覧する。
### 一覧表示・検索・レポート
- 「今何がある?」「進行中のタスクは?」のような問いには、backlog.mdの内容をそのまま流用し、聞かれた範囲(全体、特定ステータス、特定優先度など)だけを整形して会話内に表示する。ファイルを書き換える必要はない。
- 長いバックログの要約を求められたら、件数(進行中◯件・未着手◯件・完了◯件)と主要な高優先度タスクを中心にまとめる。
## 進め方

1. `backlog.md` を探す/読む(なければ上記フォーマットで新規作成してよいか確認)。
2. ユーザーの依頼を上記の操作のいずれかにマッピングする。
3. ファイルを編集する操作(追加・更新・並べ替え)の場合は、編集後に変更点を短く要約してユーザーに伝える(何をどう変えたか。ファイル全体を貼り直す必要はない)。
4. 一覧表示・検索のみの場合はファイルを変更せず、会話内で回答する。

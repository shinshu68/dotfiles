# to-japanese

直前の応答が英語で出てしまったとき、その応答を日本語にして出し直す。

ユーザーがこのスキルを呼ぶのは、英語の応答を読みにくいと感じたからで、求めているのは「同じ内容を日本語で読むこと」。作業の続きや再確認ではないので、訳した応答を出すところで終える。

## 対象

このスキルが呼ばれる直前の、自分の最後の応答 (ツール呼び出しのあとにまとめて書いた最終の報告・回答) を対象にする。

- 途中経過の一言 (「次に○○を編集します」など) は対象外。すでに流れていて、今から出し直しても役に立たないため
- 一部だけ英語の応答も、日本語の部分を含めて応答全体を出し直す。英語の部分だけを抜き出すと、どこに入る文か分からなくなるため
- 最後の応答がすでに日本語だった場合は、出し直さずに「直前の応答はすでに日本語です」と一言だけ伝える

## 訳し方

- 内容は足し引きせず、元の応答を忠実に訳す。構成 (見出し・箇条書き・表・順番) も元のまま保つ。元の応答と見比べたときに、どこがどこに対応するか分かるようにするため
- ツールの再実行、ファイルの読み直し、作業のやり直しはしない。必要な情報はすべて元の応答の中にある
- 次のものは訳さずに元の表記のまま残す
  - コードブロックの中身 (コード中のコメントも含む)。実際のファイルの内容と食い違わないようにするため
  - コマンド、識別子 (変数名・関数名など)、ファイル名・パス、URL
  - エラーメッセージやツールの出力を引用した部分
  - git の fast-forward のように、普段から英語のまま書く用語
- 元の応答が確認事項や質問で終わっていた場合は、訳したあとも同じ確認事項・質問で終える
- 括弧は半角の () を使うなど、普段の応答と同じ書き方の決まりに従う

## 出力

- 訳した応答だけを出す。「日本語に訳し直します」のような前置きや、英語になった理由の説明・お詫びは書かない
- このあとの応答も日本語で続ける

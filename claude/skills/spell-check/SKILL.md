# スペルチェックと辞書登録 (spell-check)

## これは何をするスキルか

VS Code の拡張機能 Code Spell Checker は、辞書にない単語に波線を引く。Claude Code で書いたコードには
ライブラリ名・コマンド名・略語などの「タイプミスではないが辞書にない単語」が多く含まれ、波線が
気になる原因になる。このスキルはコミット前に未登録の単語を洗い出し、次の2つを行う。

- タイプミスは修正する
- 問題ない単語は、全プロジェクト共通で参照される辞書ファイルに登録する

判定の結果は必ずユーザーに説明し、承認を得てから修正・登録する。誤った単語が辞書に入ると、
以後はそのタイプミスが検出されなくなるため。

## 設定

- **辞書ファイル**: `~/.config/cspell/words.txt`
  - 実体は dotfiles の `config/cspell/words.txt`。WSL・Windows とも `~/.config/cspell` がそこへのリンクになっている(ansible の link ロール・vscode ロールで作成)。
  - VS Code 側の `cSpell.customDictionaries`(dotfiles の `vscode/settings.json`)もこのパスを指す。
  - ファイルが存在しない場合は、リンクが作られていない可能性が高い。勝手に作成せず、ansible の link ロール(Windows では vscode ロール)の実行をユーザーに案内して止まる。

## 辞書ファイルの書式

Code Spell Checker の単語リストファイルは1行1単語で、`#` で始まる行はコメントとして無視される。
この性質を使い、プロジェクトごとの見出しと単語ごとの説明をコメントで残す。

```text
# ===== project-a =====
# 動画ダウンロードに使う外部ライブラリ名
ytdlp
# 設定ファイル読み込み関数名の一部
confload

# ===== project-b =====
# 試合データ取得 API のエンドポイント名
matchv5
```

- 見出しは `# ===== <プロジェクト名> =====`。プロジェクト名は git リポジトリのルートディレクトリ名(`git rev-parse --show-toplevel` の末尾)を使う。
- 説明は単語の **直前の行** にコメントとして書く。単語と同じ行の後ろに書く形(`word # 説明`)は、拡張機能のバージョンによっては単語の一部として扱われるおそれがあるため使わない。
- 見出しで分けても、辞書は全プロジェクトで共通に効く。見出しは整理と説明のためのもの。
- 既存の行(他のプロジェクトの見出し・単語・説明)は変更・並べ替えしない。

## 手順

### 1. 対象ファイルを確認する

```
git diff --staged --name-only --diff-filter=ACMR
```

- ステージ済みの変更がない場合は、その旨を伝えて止まる。未ステージの変更を勝手に対象にしない。
- ロックファイル(`package-lock.json`、`poetry.lock` など)、画像などのバイナリ、自動生成ファイルは対象から外す。

### 2. cspell の CLI を用意する

```
cspell --version
```

使えない場合は、勝手にインストールしない。次の2案を理由とともに示し、ユーザーに選んでもらう。

- `npm install -g cspell` でグローバルにインストールする(以後すぐ使える)
- 毎回 `npx --yes cspell` で実行する(グローバル環境を汚さないが、初回にダウンロードが発生する)

### 3. 一時設定ファイルを作り、cspell を実行する

cspell の CLI は VS Code の設定を読まないので、辞書ファイルを読み込む一時設定を作る。
辞書ファイルのパスは `~` を展開した絶対パスで書く。

`/tmp/spell-check-cspell.json`:

```json
{
  "version": "0.2",
  "dictionaryDefinitions": [
    { "name": "global-words", "path": "<辞書ファイルの絶対パス>" }
  ],
  "dictionaries": ["global-words"]
}
```

プロジェクトに cspell の設定ファイル(`cspell.json`、`.cspell.json`、`cspell.config.*` など)がある場合は、
`"import": ["<そのファイルの絶対パス>"]` を追加して、プロジェクト側の設定も反映させる。

実行する。

```
cspell --config /tmp/spell-check-cspell.json --no-progress --no-summary --show-context --no-must-find-files <対象ファイル...>
```

未知語があると終了コードが 0 以外になるが、エラーではない。出力の `ファイル:行:列 - Unknown word (単語)` を読む。

プロジェクトの `.vscode/settings.json` に `cSpell.words` がある場合、そこに載っている単語は VS Code
では既に登録済みなので、結果から除外する。

未知語が1つもなければ「未登録の単語はありませんでした」と一言伝えて終わる(commit-suggest から
呼ばれた場合は、そのまま commit-suggest の次の手順に戻る)。

### 4. 単語ごとに判定する

同じ単語は1つにまとめ、出現箇所の前後のコードを読んで判定する。判定は次の3種類。

- **タイプミス**: 本来の綴りが明らかなもの。正しい綴りの候補と、タイプミスと判断した根拠(同じファイル内に正しい綴りの識別子がある、英単語として存在しない、など)を示す。
- **問題ない単語**: ライブラリ名・コマンド名・製品名・略語・プロジェクト固有の名前・他言語のローマ字表記など。**何の単語か** を具体的に説明する(例: 「Python の HTTP ライブラリ名」「`git` のサブコマンド名」「このプロジェクトの設定キー名」)。
- **判断できない**: どちらとも言えないもの。推測で決めず、そう判断した理由を添えてユーザーに尋ねる。

識別子の一部(`camelCase` や `snake_case` の一部分)として検出された単語は、識別子全体を見て判断する。
識別子名そのものが誤っている場合(例: `recieveData`)はタイプミスとして扱う。

### 5. 判定結果を提示し、承認を得る

次の並びで提示する。

```
### タイプミス(修正が必要)
- `recieve` → `receive`(src/api.py:12 ほか2か所)
  英単語として存在せず、同じファイルの他の箇所では receive と書かれているため。

### 問題ない単語(辞書に登録)
- `ytdlp`(src/download.py:3)
  動画ダウンロードに使う外部ライブラリ名。

### 判断できない単語
- `cnfg`(config/load.py:8)
  config の略記にも、タイプミスにも見えるため。
```

提示後、選択肢の UI(AskUserQuestion)で「この内容で修正・登録する」「一部を変更する」を出して止まる。
「一部を変更する」が選ばれた場合や判断できない単語がある場合は、ユーザーの指示を受けてから進む。
複数の単語について確認していて、返答が一部にしか触れていない場合は、残りを自分で決めずに改めて尋ねる。

### 6. 修正と登録を行う

承認された内容だけを反映する。

**タイプミスの修正**

- 対象ファイルを修正したら、`git diff --name-only`(未ステージの差分)でそのファイルに修正以外の未ステージ変更がないか確認する。
  - なければ `git add <ファイル>` で修正をステージに含める。
  - 修正以外の未ステージ変更もある場合は、意図しない変更までステージしないよう、`git add` せずにその旨を伝えてユーザーに任せる。

**辞書への登録**

- 辞書ファイルの中から、このプロジェクトの見出し(`# ===== <プロジェクト名> =====`)を探す。
  - あれば、その見出しの区切り(次の見出しの直前、またはファイル末尾)に追記する。
  - なければ、ファイル末尾に空行を1行挟んで見出しを作り、その下に追記する。
- 単語ごとに「説明のコメント行」「単語の行」の2行を書く。説明は手順4で示した「何の単語か」を1行に収める。
- 既に辞書にある単語(大文字・小文字の違いだけのものを含む)は重複して追加しない。

辞書ファイルは dotfiles のリポジトリにあるが、このスキルでは dotfiles のコミットや push はしない。
「辞書ファイルに N 語を追加しました」と伝え、dotfiles 側のコミットはユーザーに任せる。

### 7. 終了する

修正したファイル、追加した単語の一覧を短く報告して終わる。commit-suggest から呼ばれた場合は、
続けて commit-suggest の手順(ステージ済み変更の確認以降)に進む。

## 注意点

- 承認前に、ファイルの修正や辞書への追加をしない。
- 辞書ファイルの既存の内容は、追記以外で変更しない。
- 単語の説明に、API キーやアカウントの識別情報など秘匿すべき情報を書かない。秘匿情報に見える文字列(ランダムな英数字の並びなど)が未知語として検出された場合は、辞書に登録せず、コードに秘匿情報が含まれていないかユーザーに知らせる。
- 一時設定ファイル `/tmp/spell-check-cspell.json` は実行のたびに作り直してよい。

# pr-done

GitHub上でPRを手動マージした後の後片付け（developの同期 + マージ済みブランチの削除 + 対応するバックログタスクの完了）を行うスキルです。

## いつ使うか

- ユーザーが `/pr-done` と入力したとき
- 「PRマージしたからdevelopに反映して」「developを最新化して」「マージ済みのブランチ削除して」など、PRマージ後の後片付けを依頼されたとき
このスキルは **PRを手動でマージした後** に使うことが前提です。PRの作成自体はこのスキルの範囲外です（prスキルなど別のスキルを使ってください）。

## 何をするか

1. 未コミットの変更がないか確認する（あれば安全のため中断する）
2. ローカルの `develop` ブランチに切り替える
3. `origin/develop` の最新を `git pull` で取り込む
4. `develop` にマージ済みのローカルブランチを `git branch --merged develop` で洗い出す
5. `develop` / `main` / `master` は保護し、それ以外のマージ済みブランチを `git branch -d`（安全な削除）で削除する
6. マージされたPRに対応するバックログタスクを特定し、`/backlog` スキルで完了にする（詳細は下記「バックログタスクの完了」を参照）
削除は確認なしで自動的に行いますが、`git branch -d` は「developに未マージのブランチ」を削除できない安全なコマンドなので、作業中のブランチを誤って消す心配はありません。

## 実行方法

リポジトリのルートで以下を実行してください:

```bash
bash /path/to/pr-done/scripts/sync_and_cleanup.sh
```

Claude Codeなど、このスキルのディレクトリがそのまま使える環境では、`scripts/sync_and_cleanup.sh` をそのまま実行すればOKです。

## バックログタスクの完了

ブランチの掃除が終わったら、今回マージされたPRに対応するバックログタスクがあれば `/backlog` スキルで完了にします。これはgitコマンドではなく、Claude自身が会話の文脈から判断して行うステップです。**そもそも今回のPRにバックログタスクが紐づいているかどうか自体も、文脈から判断すること**（すべてのPRにバックログタスクがあるとは限らない）。

1. **バックログタスクに紐づく作業かどうかをまず判断する**: このセッション内の直近のやり取り（`pr` スキルで作成したPRのタイトル・内容、ユーザーがそれまでに言及した内容など）を見て、今回の作業がそもそもバックログタスクに紐づくものかを判断する。
   - 会話の中でバックログタスクやチケットIDへの言及が一切なく、紐づく気配もない（例: ちょっとした修正やこのスキル自体の設定変更など）場合は、バックログタスクは無いものとして扱い、完了処理はスキップする。無理に「関係ありそうなタスク」を探しにいったり、IDを推測したりしない。
   - バックログタスクに紐づきそうな気配はあるが、確信が持てない場合（後述）はユーザーに確認する。
2. **紐づくタスクがあり、IDが1つに絞り込める場合**: 確認を挟まずに `/backlog <ID> を完了にする` を実行する（`/backlog` スキルを、そのIDを完了にする指示として呼び出す）。
3. **紐づくタスクがありそうだが、IDが分からない・複数候補があり絞り込めない場合**: 推測でIDを決め打ちしない。ユーザーに「どのバックログタスクを完了にすればよいか」を確認してから `/backlog` を呼び出す。
4. **バックログタスクが無いと判断した場合**: `/backlog` は呼び出さず、完了処理をスキップしたことだけ簡潔に触れる（大げさに確認を取る必要はない）。
5. ブランチ削除の結果と合わせて、どのタスクを完了にしたか／バックログタスクなしと判断してスキップしたか／確認待ちかを最後にまとめて報告する。
## 実行結果の伝え方

スクリプトの出力をそのままユーザーに見せ、以下を明確にすること:

- developが最新化されたこと
- 削除されたブランチの一覧（削除対象がなければその旨も伝える）
- バックログタスクの扱い（完了にした／タスクなしと判断してスキップした／IDが分からずユーザーに確認中、のいずれか）
## 注意点・エッジケース

- **未コミットの変更がある場合**: スクリプトはエラーで中断します。ユーザーにコミットまたは `git stash` を促してください。
- **developブランチがローカルに存在しない場合**: エラーで中断します。`git fetch && git checkout -b develop origin/develop` などでローカルにdevelopを作る必要がある旨を伝えてください。
- **リモートブランチは削除しない**: このスキルはローカルブランチのみを対象とします。リモート（`origin`）の対応ブランチを消したい場合は、ユーザーに別途確認してから `git push origin --delete <branch>` を提案してください（勝手に実行しない）。
- **develop/main/masterという名前以外の保護ブランチがある場合**（例: `staging`）: `scripts/sync_and_cleanup.sh` 内の `PROTECTED_BRANCHES` にブランチ名を追加してください。
- **そもそもバックログタスクに紐づくPRかどうか不明な場合**: 「バックログタスクがある前提」で動かない。紐づきが読み取れなければタスクなしとして扱ってよい。
- **バックログタスクIDが会話中から特定できない場合（紐づきはありそうだがIDが不明）**: 憶測でタスクを完了にしない。必ずユーザーに確認する。
- **`/backlog` スキル自体が呼び出せない・存在しない場合**: エラーをそのままユーザーに伝え、手動での完了操作を促す。

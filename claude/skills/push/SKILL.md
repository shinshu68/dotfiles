# /push

このスキルは `/push` コマンド専用です。現在のブランチをGitHubにプッシュします。一般的なgitのヘルプや他のgit操作、自然な言い方でのプッシュ依頼には使わないでください。`/push` が明示的に呼び出されたときだけ使用します。

## 手順

1. **gitリポジトリであることを確認する。** `git rev-parse --is-inside-work-tree` を実行する。失敗したら、gitリポジトリではないことをユーザーに伝えて中断する。
2. **現在のブランチを取得する。** `git branch --show-current` を実行する。空の場合はdetached HEAD状態なので、その旨をユーザーに伝えて中断する(何をプッシュすべきか推測しない)。
3. **未コミットの変更を確認する。** `git status --porcelain` を実行する。出力があれば未コミットの変更がある旨を軽く伝えるが、プッシュ自体はブロックしない(プッシュされるのはコミット済みの変更だけなので、これは単なる注意喚起であり止める理由にはならない)。
4. **`origin` が存在することを確認する。** `git remote get-url origin` を実行する。失敗したら、`origin` リモートが設定されていないことをユーザーに伝えて中断する(リモートURLを勝手に推測しない)。
5. **ブランチにupstreamが設定されているか確認する。** `git rev-parse --abbrev-ref --symbolic-full-name @{u}`(stderrは抑制)を実行する。
   - 成功した場合は既にリモートを追跡しているので、そのまま `git push` を実行する。
   - 失敗した場合はupstream未設定なので、`git push -u origin <branch>` を実行してupstreamをoriginに設定しつつ同時にプッシュする。
6. **プッシュ前に、何が送られるかを把握しておく。** upstreamが存在する場合は `git log @{u}..HEAD --oneline` でこれからプッシュされるコミットが分かるので、件数を最終報告に含める。upstreamを初めて設定する場合は、そのブランチの全コミットが送られる。
7. **結果を素直に報告する。** 失敗時に勝手な対処を試みず、実際のエラーを読んでわかりやすく説明する。
   - **non-fast-forward(拒否)**(リモートに手元にないコミットがある)→ その旨を説明し、まず `git pull --rebase`(または `git pull`)を提案する。自動でforce pushは絶対にしない(リモートの履歴を破壊する可能性があり、それを判断するのはこのスキルの役割ではない)。
   - **認証・権限エラー** → GitHubの認証情報がこのプッシュに対して機能していないことをユーザーに伝える。認証情報の修正は自分で試みない。
   - **プッシュするものがない(既に最新)** → その旨を素直に伝える。これは失敗ではない。
   - **成功時** → ブランチ名、プッシュされたコミット数、upstreamを新規設定したかどうかを伝える。
## この設計にした理由

ユーザーが選んだデフォルトの挙動は次の通り: upstreamが未設定なら毎回確認せず自動で設定する、未コミットの変更があってもプッシュ自体は通す(そもそもプッシュ対象ではないため)— ただし最終報告では触れる。拒否されたプッシュに対してforce pushや独自の対処を行うことは絶対にせず、実際のエラーをそのまま伝えてユーザーに判断を委ねる。誤った判断は作業の消失につながりかねないため。

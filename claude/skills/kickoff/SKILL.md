# kickoff — 引き継ぎメモを読んで次の作業に着手する

## なぜこのスキルがあるか

前のセッションで `/handoff` が、次の作業に必要な文脈を引き継ぎメモに書き出している。ユーザーは `/clear` でコンテキストを空にしてからこのスキルを呼ぶ。つまり今の Claude の手がかりは、そのメモとリポジトリの状態だけ。ユーザーは「メモに書いた作業を始めて」と言っているので、再確認せずに作業の中身まで進めるのが期待されている (`/approve-next-step` と同じく「はい、お願いします」の短縮形)。

## 手順

### 1. 引き継ぎメモを探して読む

次の順に探す:

1. 自動メモリのディレクトリ (システムプロンプトで案内されている memory ディレクトリ。通常は `~/.claude/projects/<プロジェクト>/memory/`) の `handoff.md`
2. `~/.claude/handoff/<リポジトリ名>.md` (自動メモリが使えない環境向けの保存先)

どちらにもなければ、推測で作業を始めずに「引き継ぎメモが見つかりませんでした。何の作業を始めますか？」と短く聞いて止まる。

### 2. 前提を確かめる

メモの冒頭にある情報と、今の状態を突き合わせる:

- **リポジトリ**: メモのリポジトリと今の作業ディレクトリが違う場合は、別のプロジェクトの引き継ぎを拾っている可能性があるので、着手前にユーザーに確認する。
- **ブランチ・作業ツリー**: `git status` と現在のブランチを確認する。メモの「開始時のブランチ」と違う、想定外の未コミット変更がある、といった場合は、その事実を一言添える。作業を進められるなら進めてよいが、変更を消す・上書きするような操作はしない。
- **作成日時**: 数日以上前のメモなら、内容が古い可能性があるので一言触れる (着手はしてよい)。

### 3. メモを片付ける

読み終えたら、引き継ぎメモは役目を終えた一時ファイルなので片付ける。残しておくと、後のセッションで終わった作業を再開してしまう恐れがある。

- `handoff.md` (または `~/.claude/handoff/<リポジトリ名>.md`) を削除する。
- `MEMORY.md` から `(handoff.md)` を指す引き継ぎの1行だけを削除する。他の行には触れない。

メモの内容はもう今の会話に読み込まれているので、削除しても困らない。

### 4. 作業に着手する

1. 冒頭で「<作業のタイトル>に着手します」と一行だけ述べ、メモの「やること」を1〜2行で要約する (何を引き継いだかがユーザーに分かれば十分)。
2. メモの「着手手順」に沿って、実際に作業を進める。計画を再提示して止まるのではなく、ブランチ作成・実装・調査などの中身まで行う。
   - バックログのタスクIDが書かれていれば、`/backlog` スキルで「#<ID>に着手します」として着手する (backlog スキルはステータス更新と作業開始の両方を行う)。
   - 「背景・決まっていること」に書かれた方針・条件は、ユーザーが前のセッションで合意したものとして守る。
3. メモの「注意点・未決事項」にユーザーの判断が必要なことがあれば、そこに差しかかった時点で聞く。最初にまとめて聞いて止まる必要はない。
4. 作業が終わったら、いつもどおり結果を報告する (動作確認の依頼など、通常の開発の流れに戻る)。

## 注意

- 着手してよいのは、メモに書かれた作業の範囲まで。メモになかった破壊的な操作 (ファイルの大量削除、force push など) は追加で行わない。
- メモの内容と今のリポジトリの状態が明らかに食い違う (書かれたファイルが存在しない、タスクが既に完了している など) 場合は、無理に進めずに状況を伝えて判断を仰ぐ。

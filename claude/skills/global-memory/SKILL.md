# グローバル教訓スキル

プロジェクト固有の `MEMORY.md` に記録された「同じ問題を繰り返さないための教訓」のうち、他のプロジェクトでも起こりうるものを、Claude Code がどのプロジェクトでも必ず読み込む `~/.claude/CLAUDE.md` に転記する。

## なぜこの形式か

`MEMORY.md` はそのプロジェクトの中でしか読まれないので、同じ種類のミスを別プロジェクトで繰り返してしまう。一方で `~/.claude/CLAUDE.md` は全プロジェクト共通で読み込まれるため、「プロジェクトを問わず気をつけるべきこと」だけを置く場所として使う。プロジェクト固有の詳細(ファイル名、関数名、社内サービス名など)をそのまま持ち込むと、他のプロジェクトでは意味が通じない指示になってしまうため、一般化してから書く。

## トリガー

ユーザーが `/global-memory` と入力したときに起動する。基本的な使われ方は、直前の会話の中で(このスキルとは別の仕組みで)プロジェクトの `MEMORY.md` に何らかの教訓が書き込まれた直後に呼ばれるケースを想定している。

## 進め方

### 1. 対象の教訓を特定する

まず会話の直近の流れを見て、直前に `MEMORY.md` へ書き込まれた内容(またはこれから書き込もうとしている内容)を特定する。該当しそうな記載が会話内に見当たらない場合は、何を教訓として記録したいのかユーザーに一言確認する。憶測で進めない。

### 2. 一般化するかどうかを判断する

教訓の内容を読んで、次のように判断する。

- プロジェクト固有の固有名詞(具体的なファイルパス、変数名・関数名、サービス名、リポジトリ名など)が含まれている → それらを取り除き、「どんな状況で・何を・どうすべきか」という一般的な行動指針の形に書き直す。
- すでに一般的な内容(例:「大きな変更の前に必ずテストを走らせる」)である → ほぼそのまま採用してよい。
判断に迷う場合や、一般化すると意味が薄まってしまいそうな場合は、一般化した案をユーザーに見せて確認してから進める。

### 3. `~/.claude/CLAUDE.md` を読む

- ファイルが存在しなければ、新規作成してよいか一言確認してから作成する。
- ファイル内に `## 全プロジェクト共通の注意点` という見出しのセクションを探す。存在しなければ、ファイル末尾にこのセクションを新規追加する(それ以外の既存の内容には触れない)。
### 4. 重複チェック

`## 全プロジェクト共通の注意点` セクション内の既存項目を読み、今回の教訓と意味的に重なるものがないか確認する。

- **ほぼ同じ内容がすでにある** → 追記せず、その旨を短くユーザーに伝えて終える。
- **関連するが微妙に違う(より具体的、より広い範囲をカバーする等)** → 新規項目として追記するのではなく、既存の項目を統合・上書きする形で更新する。
- **重複がない** → 新規項目として追記する。
### 5. 追記フォーマット

```markdown
## 全プロジェクト共通の注意点
- [YYYY-MM-DD] 一般化した教訓の一文
```

- 日付は追記した日。
- どのプロジェクトがきっかけかは書かない。ここはあくまで「プロジェクトを問わず気をつけること」の置き場所なので、出典は残さず教訓の内容だけを書く。
- 1項目1行を基本とする。背景説明が長くなりすぎる場合は、一文に収まるよう要約する。
### 6. 結果をユーザーに伝える

ファイルを編集したら、何を・どう書いたか(新規追記/統合/スキップのどれだったか)を短く要約して伝える。ファイル全体を貼り直す必要はない。
